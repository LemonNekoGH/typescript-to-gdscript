# TS plugin notes

Edge cases for the TypeScript language service plugin. The project overview is `PROJECT.md` at the repo root.

- ts-plugin options (in `compilerOptions.plugins[]`): `debug` (boolean, default false) — verbose tsserver-log tracing; `debugLog` (string, optional) — file path; when set, both `[tstogd-plugin]` log lines and (when `debug=true`) trace lines are appended there in addition to tsserver's own log, so debug captures don't require digging through the noisy tsserver log; `disableGodotLint` (boolean, optional) — per-editor override for `tstogd.json`'s `disableGodotLint`. Defined explicitly takes precedence over the project config; omitting the key leaves the project config in effect.
- ts-plugin augmentation-diagnostic filter: user-written `export namespace Foo { ... } export class Foo` blocks (the pattern for enums / inner classes) trigger three TypeScript diagnostic codes that are correct-but-noisy for this project's layout. The plugin filters them unconditionally for in-scope `.ts` files (under `tsDir`, not `.d.ts`): `TS2434` / `TS2435` ("namespace must precede the class"), `TS2449` ("class used before its declaration"). Nothing else rides that list — `TS7029` (`noFallthroughCasesInSwitch`) in particular is deliberately NOT filtered, since it only appears when the user turned it on (see the `switch` → `match` edge case). All channels are filtered (`getSyntacticDiagnostics`, `getSuggestionDiagnostics`, `getSemanticDiagnostics`). The plugin does NOT transform tsserver's snapshot — users' source is visible as-is; the namespace+class merge is pure TypeScript declaration merging.
